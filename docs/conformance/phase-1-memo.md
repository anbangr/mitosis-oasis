# ADR: Phase-1 AgentCity Legislation Conformance Verdict

## Status

Accepted for Phase 1.

## Context

This memo records the Phase-1 legislation conformance replay for AgentCity contracts against the OASIS adapters. The replay was run from the branch root with `pytest -m conformance` on 2026-05-27 and wrote the canonical snapshot under `test/conformance/reports/0x1827cdd5211f606e9c50af170d38a6135a251592b5ed775b66e3cd3b7ba501ce/`.

contracts_sha: 0x1827cdd5211f606e9c50af170d38a6135a251592b5ed775b66e3cd3b7ba501ce

The snapshot copied into [docs/conformance/phase-1/conformance.json](docs/conformance/phase-1/conformance.json) and [docs/conformance/phase-1/conformance.md](docs/conformance/phase-1/conformance.md) is byte-identical to the report generated by that run.

What was tested:

- 145 committed Phase-1 legislation fixtures under `test/conformance/fixtures/legislation/`.
- 1,976 captured calls across ConstitutionalReview, LegislativePipeline, CodificationModule, VotingVerifier, GovernanceRegistry, AgentRegistry, EvidenceAnchor, and helper addresses emitted by the AgentCity fixture corpus.
- The SHA gate tying every fixture `source.contracts_sha`, the live external contracts digest, and the report metadata to the same value.

What was not tested:

- Phase-2 execution and adjudication powers.
- Phase-3 support contracts and CI integration.
- Fuzzing beyond the captured fixture corpus.
- Live Synergy Demo conformance mode.
- Full ABI calldata decoding once `eth-abi` is installed.
- Complete OASIS-side implementations for AgentRegistry, EvidenceAnchor, VotingVerifier, and several GovernanceRegistry/CodificationModule surfaces.

## Verdict

PASS

The Phase-1 gate is PASS because PASS-of-non-GAP is 96.51%, which is above the 95% threshold, and ERROR is 0. The GAP count is intentionally not hidden by the verdict: 1,289 calls remain outside the current OASIS adapter surface and should drive follow-up implementation scope.

## Top FAILing Functions

All FAILs are in ConstitutionalReview:

| Function | FAIL | Root-cause hypothesis | Ticket |
| :--- | ---: | :--- | :--- |
| `ConstitutionalReview.reviewProposal(bytes32,bool,bytes32)` | 13 | The replay driver is not carrying ConstitutionalReview EventBus emissions into the returned call events consistently, and some revert paths still rely on fixture-derived selectors rather than modeled OASIS state. | No ticket yet; file follow-up. |
| `ConstitutionalReview.setConstitutionalParams(address)` | 3 | Address update and AccessControl-like revert semantics are represented only in the replay adapter, not in a production ConstitutionalParameters counterpart. | No ticket yet; file follow-up. |
| `ConstitutionalReview.getVerdict(bytes32)` | 2 | Stored verdict state diverges when preceding reviewProposal calls fail event/result comparison, so query calls observe different replay state than the fixture expects. | No ticket yet; file follow-up. |
| `ConstitutionalReview.hasPassed(bytes32)` | 2 | Boolean return data differs for failed verdict replay, likely from verdict encoding/state normalization drift in the adapter. | No ticket yet; file follow-up. |
| `ConstitutionalReview.pause()` | 2 | Pause events are mapped through OASIS EventBus types, but the end-to-end replay snapshot sees empty or mismatched Solidity event sequences. | No ticket yet; file follow-up. |
| `ConstitutionalReview.getReview(bytes32)` | 1 | Review tuple serialization does not yet match the Solidity fixture layout for all replayed state. | No ticket yet; file follow-up. |
| `ConstitutionalReview.unpause()` | 1 | Unpause event mapping has the same EventBus-to-Solidity event propagation gap as pause. | No ticket yet; file follow-up. |
